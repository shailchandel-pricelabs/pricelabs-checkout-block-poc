Blocking a checkout date, three ways

Today, keeping guests from checking out on Dec 25 means building a generic override, finding a hidden toggle, then re-describing that single date as a day-of-week rule. Below are three interaction directions that collapse this into: pick date(s), pick the restriction, done — same underlying model, different UI shape. Use the tabs to compare them for the dev conversation.

The real cost: reframing one exact date as a recurring weekday rule scoped to a narrow window — a workaround, not a designed path.

How this maps internally (for the dev conversation)

The user never sees any of this in any of the three variants — but nothing about the backend model has to change. Each applied date still becomes a Date-Specific Override with check-in/checkout rules and a day-of-week exclusion; the UI now assembles it in one pass instead of asking the user to.

Dec 25, 2026 selected → weekday = Friday → override: Dec 25–Dec 25, exclude Fri, Block Checkout

Non-adjacent picks (e.g. Dec 25 + Jan 1) become one override per contiguous run, or one per date if weekdays collide across the range — resolved silently, and listed as one line each under "Active restrictions" regardless of how many overrides it took underneath.
